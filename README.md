# CityLogistics — Frontend

Клиентская часть проекта CityLogistics: HTML/CSS и Vanilla JS, запросы к API через `fetch`.
Данные берёт из core (`http://localhost:8080/api`), а вход идёт через Keycloak
(`http://localhost:8180`). Бэкенд, схема проекта и
инструкция запуска описаны в README [citylogistics-core](https://github.com/KopachYahor/citylogistics-core).

## Страницы

- `index.html` — главная, вход (кнопка ведёт на страницу Keycloak) и регистрация (имя, email,
  пароль, роль; для водителя ещё телефон). Сюда же Keycloak возвращает браузер после входа.
- `html/order.html` — создание заказа (`POST /api/orders`).
- `html/order-status.html` — отслеживание: статус выбранного заказа, по умолчанию самого нового.
- `html/profile.html` — кабинет клиента: статистика, текущий заказ, история заказов и отмена
  заказа, пока водитель не назначен (`PATCH /api/orders/{id}/cancel`, только статус `NEW`).
- `html/driver-dashboard.html` — кабинет водителя: назначенные заказы и кнопки смены статуса
  (`ACCEPTED → IN_TRANSIT → ARRIVED → DELIVERED`).
- `about`, `price`, `information`, `feedback`, `contacts`, `driver-form` — информационные страницы.

### Вход через Keycloak (Authorization Code + PKCE, `js/auth.js`)

1. «Войти»: `startLogin` придумывает случайный `code_verifier`, отправляет Keycloak только его
   хеш (`code_challenge`, SHA-256) и уводит браузер на страницу входа Keycloak. Пароль
   вводится там, фронтенд его не видит.
2. Keycloak возвращает браузер на `index.html?code=...&state=...`. `handleLoginCallback`
   сверяет `state` и меняет `code` на токены, прикладывая исходный `code_verifier`.
3. `finishLogin` запрашивает `/api/auth/me` и по роли открывает нужный кабинет.
4. Access token живёт 5 минут. Перед каждым запросом `apiFetch` вызывает `ensureFreshToken`:
   если до конца срока меньше 30 секунд, токен обновляется по refresh token. Если сессия
   Keycloak закончилась (30 минут без действий), снова открывается вход.
5. «Выйти» (`keycloakLogout`) очищает токены и завершает сессию в Keycloak.

Регистрация идёт через core (`POST /api/auth/register`), после неё сразу открывается вход
Keycloak с подставленным email. Токен передаётся в заголовке `Authorization: Bearer <token>`.
Пункты меню, ненужные для роли, скрываются — но это только удобство: права проверяет
бэкенд (`403` при попытке вызвать чужой эндпоинт).

## Как устроен код

- `js/auth.js` — вход через Keycloak (см. выше): `startLogin`, `handleLoginCallback`,
  `ensureFreshToken`, `tokenClaims`, `keycloakLogout`. Подключается на каждой странице до `script.js`.
- `js/script.js` — общий код всех страниц и логика клиентских страниц. Важные функции:
  - `apiFetch(path, options)` — запрос к API с токеном, при необходимости обновлённым. На `401`
    очищает сессию и открывает вход, поэтому страницам не нужно обрабатывать это самим;
  - `readJson(response)` — тело ответа как JSON, не падает на HTML-странице ошибки;
  - `pageUrl(page)` — путь к странице от текущей (страницы лежат в корне и в `html/`);
  - `escapeHtml(value)` — экранирование данных перед вставкой через `innerHTML` (защита от XSS);
  - `STATUS_LABELS` — статусы заказа по-русски.
- `js/driver-dashboard.js` — кабинет водителя, использует функции из `script.js`
  (подключается после него).
- `js/burger.js` — мобильное меню, `js/faq.js` — аккордеоны на `feedback.html`.

Если открыть страницу без входа, где нет окна входа (например, `order.html`), иконка профиля
сразу ведёт на страницу входа Keycloak, а «Создать кабинет» — на `index.html#register`.

## Как запустить

1. Запустить бэкенд по README core (core на 8080, driver-service на 8082, Keycloak на 8180).
2. Запустить статический сервер **на порту 5500**: только для него бэкенд разрешает CORS, а
   Keycloak — возврат после входа (`redirectUris` в `realm-export.json` core):
   ```bash
   npx live-server --port=5500
   ```
   или расширение Live Server в VS Code.
3. Открыть `http://localhost:5500` (или `http://127.0.0.1:5500`).

Без Node.js подойдёт и Python: `python -m http.server 5500` в папке репозитория.
Если после обновления кода страница ведёт себя по-старому, браузер взял файлы из кэша:
обновите страницу с `Ctrl+F5`.

## Известные ограничения

1. **Цена фиксированная.** Расчёта стоимости нет: каждый заказ стоит 300 BYN (`ORDER_PRICE`
   в `js/script.js`), это написано на форме заказа.
2. **Часть полей формы заказа не сохраняется.** Телефон получателя, дату, время, тип груза,
   вес, количество мест и условия бэкенд не принимает, поэтому фронтенд их не отправляет.
3. **Адрес API зашит в код** (`API_URL` в `js/script.js`).
4. **Токены хранятся в `localStorage`**, в том числе refresh token. Данные с сервера
   экранируются перед вставкой в страницу (`escapeHtml`), но если XSS всё же появится,
   скрипт сможет прочитать токены. Надёжнее — паттерн Backend-for-Frontend: токены держит
   сервер, а браузер получает cookie с флагом `HttpOnly`.
5. **Адрес Keycloak зашит в код** (`KEYCLOAK_URL` в `js/auth.js`).
6. **Заглушки, которые выглядят рабочими, но не связаны с бэкендом:**
   - «Настройки» и «Мои адреса» в профиле;
   - «Редактировать» в профиле — данные сохраняются только в `localStorage`;
   - карта и «Построить маршрут» на `order-status.html`: Яндекс.Карты подключены с ключом
     API, но кода построения маршрута нет. Ключ JS API Яндекса всё равно виден в браузере,
     но его стоит ограничить по домену в кабинете разработчика Яндекса;
   - окно «Отследить маршрут» с оценкой водителя на `order.html`;
   - формы заявок на `feedback.html` и `driver-form.html`, кнопка «Оплатить» на `price.html` —
     показывают сообщение, но никуда не отправляют данные.
